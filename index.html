nocap

Anti-screenshot, anti-AI display for secrets on screen.

Content is split into frames that alternate at your display's refresh rate. Each frame is noise; their mean is the content. Your visual system does the averaging, so you read it — a single screenshot does not. And the text never enters the DOM, so page-reading AI agents get nothing at all.

How DevTools defeats it

Listing a defeat without saying how invites the assumption it is theoretical, so here is the whole picture. scramble — an optional mode that stores glyphs shuffled and paints them back into place — moves several of these and is shown in the last column. It does not move the one that matters.

AttackDefaultWith scramble

The first row is the one that settles it, and no mode changes it: the canvas must hold the correctly-arranged image, or you could not read it either. A short run of frames averaged together is the plaintext — the demo recovers it identically with and without scramble. Scrambling protects how the value sits in JS memory — worth having, and it does blunt the one-line fillText dump — but it is obfuscation, not encryption. The shuffled glyphs and their position map are both live fields on the element, and the setter still receives the plaintext before any of it happens.

The real line is automated pipeline vs. targeted attacker. nocap defeats the pipeline — screenshots, scrapers, DOM-reading agents, OCR — and never the person who has decided to come after the value. Both attacks run live in the demo.

    Use it

    npm i nocap
    import 'nocap';

<nocap-secret hold auto-hide="6"></nocap-secret>

document.querySelector('nocap-secret').secret = await fetchAccountNumber();

    Set .secret from JS. Putting the text in markup works — it is read once and erased from the DOM — but it was in the HTML source on the way there, which defeats the point. It auto-hides on tab switch and window blur, which is when a screen share usually starts.

    Why text, and not photographs

    Text is essentially two-tone, so it survives being crushed into a narrow value band that would turn a photograph to mush. That means you can run amplitude 110+, where a single frame retains no usable signal. The tuning bench shows exactly where this stops working, over public-domain paintings.

    SplitLeak
    RGB channel split1.000
    Decoy image as modulator0.929
    Pixel interleave ×20.693

    Two findings worth internalising. Splitting where pixels are does nothing — only randomizing what they say works. Recognition survives losing colour, losing 90% of pixels, blur, and quantization, so channel splitting and pixel interleaving both leak badly. And noise amplitude is the only lever; frame count is not a substitute.

    Safety

    Noise is per-pixel and zero-mean, so every frame carries the same local mean luminance as the source. The alternation is a high-spatial-frequency contrast reversal, not a full-field flash — the mechanism 6-bit panels use for FRC dithering — which keeps it out of the large-area-flash regime WCAG 2.3.1 targets. It is still moving high-contrast content: hold is the default pattern because it keeps the flicker on screen only while the pointer is down. Always offer an opt-out.
