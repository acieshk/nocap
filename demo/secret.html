nocap-secret

Text is the case where this technique earns its keep. It is essentially two-tone, so it survives being crushed into a narrow value band that would turn a photograph to mush. The default is amplitude 96 with a 3px noise block — high enough to mask, low enough that the alternation still fuses on a 60Hz display.

The text is rasterised straight to a canvas inside a closed shadow root, so it never becomes a DOM node. That is what takes it out of the inspector, the accessibility tree, Reader mode, Save Page As, and every text-scraping extension at once. It also means the DOM-reading AI agents and LLM scrapers that work off the accessibility tree see nothing at all — not noise, nothing.

The last row is the honest one. This does not hide the value from anyone with DevTools and intent: the string is a live JS value, so a breakpoint, a heap snapshot, or one canvas.toDataURL() retrieves it. Nothing running in a browser can prevent that — the client belongs to the user.

Extra: scrambled glyphs

scramble stores the characters shuffled, along with a separate map of where each belongs, and paints each glyph back into its real slot. Nothing in the element is ever the plaintext in order.

wraps CanvasRenderingContext2D.fillText, then reveals each
This is obfuscation, not encryption. Both the shuffled glyphs and the position map are live fields on the element, so anyone who reads both reconstructs the value at once. What it buys is narrower: the plaintext never exists as a contiguous string, so a heap-snapshot search for it fails, and the one-line fillText hook that otherwise defeats this component now yields the character multiset and the length without the arrangement. An attacker has to hook drawImage as well and correlate the two. It raises the cost of a casual poke. It does not stop someone who has decided to extract the value.

Fake values

Noise tells an attacker the capture failed, so they take another. A value in the right shape does not. With fake on, one of the two frames carries a plausible wrong value instead of noise.

Fake mode needs a maskable palette — a masking ratio of 1.0 or more. Swapping one glyph for another means a pixel has to travel the whole text-to-background distance, so if it lacks the headroom for that it only moves part way and the real value ghosts through both frames. This example uses #9ea6b4 on #6b7280 (ratio 1.42); the higher-contrast pair used above scores 0.10 and shows the real number in both frames. Check with checkPalette() before enabling it.

Offsets also have to sum to zero, so if one plane carries the decoy the other must be 2 x target - decoy and reads as a ghosted negative. A single capture has roughly even odds of landing on either — better than noise, but not "every capture looks legitimate". Both frames are shown above so you can judge that for yourself.

Usage

import 'nocap';

const el = document.querySelector('nocap-secret');
el.secret = await fetchAccountNumber();   // from JS — never in the HTML source

Setting the text in markup also works — it is read once and erased from the DOM — but it was in the HTML source on the way there, which defeats the point. Use the property.

It auto-hides on tab switch and window blur, which is when a screen share usually starts. auto-hide="N" adds a timeout; hold requires a held pointer, which keeps the flicker on screen for as little time as possible.
